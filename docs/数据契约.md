# 数据契约（IND-1）

> **本文是"两边怎么对接"的唯一依据。** 破坏性变更必须递增 `contractVersion` 并在 §7 登记。
> 契约版本当前为 **1.0**（见 `beacon/__init__.py` 的 `CONTRACT_VERSION`）。

## 1. 三层数据形态

```
源响应 ──适配器──▶ Observation ──漏斗──▶ Candidate ──写回──▶ 目标文档
                      │                      │
                      └──▶ feed.jsonl        └──▶ changes.md / proposals/
                          （中性产物，给任何 app）
```

**三种形态的用途不同，不要混用**：

| 形态 | 是什么 | 谁在用 | 稳定性 |
|---|---|---|---|
| `Observation` | 一条原子观测（某指标在某期间的值） | 内部；也是 Feed 的每一行 | 契约，破坏性变更需递增版本 |
| `Candidate` | 一条待审的变更（改什么、为什么这个级别、凭什么） | 人审；**不对外承诺兼容** | 内部结构，随实现演进 |
| `feed.jsonl` | 全部 Observation 的落地形式 | **任何** app | 契约 |

## 2. `feed.jsonl` —— 中性产物

一行一个 JSON 对象，无 BOM，UTF-8，末尾换行。**不含任何 app 的专有语义**（由测试强制）。

```jsonc
{
  "indicator": "us.treasury.dgs10",       // 指标 id
  "period": "2026-09-21",                 // 期间：YYYY-MM | YYYY-Qn | YYYY-MM-DD
  "value": 4.96,                          // 有限数值（永不为 null / NaN）
  "unit": "%",                            // 规范化单位，取值见 §3
  "caliber": "level",                     // 口径，取值见 §3
  "source": {
    "name": "美国财政部（美国国债收益率曲线）",
    "url": "https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10&cosd=2025-08-19",
    "tier": "L2",                         // L1 一手 | L2 分发渠道 | L3 媒体（永不出现在 Feed 里）
    "upstream": "美国财政部 / 美联储",      // L2 必填，如实标注一手机构
    "published_at": "2026-09-21",         // 数据发布日（非抓取日）
    "channel": "FRED"                     // 实际经手的渠道；L1 为 null
  },
  "provenance": {
    "fetched_at": "2026-09-23T05:42:38.770513Z",
    "http_status": 200,
    "from_cache": false,
    "raw_sha256": "33b926f7…"
  }
}
```

### 2.1 调用方必须知道的三件事

| # | 事实 | 为什么重要 |
|---|---|---|
| 1 | **同一 `indicator` 可能有多个 `caliber`** | 例如 PMI 同时有水平值（`level`）与同比（`yoy`）。只按 `indicator` 聚合会把两者混在一起。 |
| 2 | **`period` 的粒度由数据本身决定**，同一指标不会混用粒度 | 月度就是 `YYYY-MM`，日度就是 `YYYY-MM-DD`。刻度标签直接用它。 |
| 3 | **某指标某期缺失 = 这条不存在**，不是 `null`、不是 `0` | 铁律：抓不到就不产。调用方不得用旧值填充或插值。 |

### 2.2 `feed.meta.json`

```jsonc
{
  "contractVersion": "1.0",
  "beaconVersion": "0.1.0",
  "generatedAt": "2026-09-23T05:42:38.821785+00:00",
  "sources": ["fred", "eastmoney", "csindex"],   // 本次真正取到数据的源
  "failures": [{"source": "fred", "reason": "非 2xx 响应（HTTP 503）"}],
  "indicators": ["cn.index.pe.000300", "…"],
  "counts": {"observations": 3695, "byIndicator": {"…": 273}}
}
```

> **`failures` 非空不代表这次运行失败**，只代表那几个源这次没取到。
> 但调用方**必须**把 `failures` 与 `sources` 都读一遍——只读 `observations`
> 会把"没取到"误当成"数据是 0"。

## 3. 枚举表

**单位**（`unit`，只有这五个会出现在 Feed 里）

| 值 | 含义 |
|---|---|
| `%` | 百分比 / 收益率（**收益率就是百分数本身**，4.96 表示 4.96%） |
| `点` | 指数点位 / 扩散指数 |
| `倍` | 倍数（市盈率等） |
| `亿元` | 人民币亿元 |
| `bp` | 基点 |

**口径**（`caliber`）

| 值 | 含义 |
|---|---|
| `level` | 水平值（收益率、点位、价格、扩散指数） |
| `yoy` | 同比 |
| `mom` | 环比 |
| `cumulative` | 累计值（年初至今） |
| `period` | 当期值（单月 / 单季） |
| `share` | 占比 / 分位 |

**层级**（`source.tier`）：`L1` 官方一手 / `L2` 分发渠道 / `L3` 媒体线索。
`L3` **永不进入 Feed**——它在 F1 就被丢弃。

## 4. CLI 契约（IND-3）

```
beacon health   各源探活
beacon export   取数并产出 Feed（中性产物）
beacon run      跑七层漏斗，产出候选与人审文件
beacon apply    把某次运行的可合入片段写回内容
beacon status   源健康 / 上次运行 / 内容是否超期 / 待修正标记
```

**退出码**（调用方可据此判断发生了什么）

| 码 | 含义 |
|:---:|---|
| 0 | 正常。`apply` 时为"全部写回成功" |
| 1 | 有源失败或全部失败；`apply` 时为"有目标被跳过" |
| 2 | **配置 / 路径错误**（内容库不存在、映射与内容对不上、缺必需参数） |

> 0 与 1 的区别是刻意的：**"跑了但没拿到数据"不是错误，而是需要你知道的事实**。
> 2 才是"你给的东西不对"。

**路径一律由参数传入**，不猜父项目位置：

| 参数 | 用途 |
|---|---|
| `--content-dir` | 内容库目录（`run` / `apply` / `status`） |
| `--cache-dir` | 缓存与抓取日志（默认 `./.beacon-cache`） |
| `--out` | 产物目录（默认 `./content-candidates`） |
| `--mapping` / `--thresholds` / `--settings` | 覆盖包内配置 |
| `--flags` | 待修正清单（见 §5） |

## 5. `flags.json` —— Recall 侧的导出（FB-3）

**这是唯一一个由另一个 app 产出、beacon 消费的接口。** 由 Recall 侧实现（`PRD.md` §5.4 A1–A3）。

### 5.1 格式

```jsonc
{
  "schemaVersion": "1.0",                  // 必填。不认识就整套不用（见 §5.2）
  "exportedAt": "2026-09-23T00:00:00Z",    // 可选
  "flags": [
    {
      "targetId": "hotspot.data.pmi-reading",  // 必填：定位到哪条内容
      "kind": "数值有误",                       // 建议取值见下
      "note": "8 月的制造业 PMI 与统计局公布的不一致",
      "at": "2026-09-22T18:00:00Z"             // 可选
    }
  ]
}
```

**`kind` 的建议取值**（不强制——它只是给人看的文字）

`数值有误` / `已过时` / `表述不清` / `其他`

### 5.2 容错读法（beacon 侧已实现，Recall 侧只需按 §5.1 写）

| 输入情况 | beacon 的行为 |
|---|---|
| 文件不存在 | **不算错**。正常继续，产物里记「未提供」 |
| 空文件 / JSON 截断 / `flags` 不是数组 | **不算错**。正常继续，但产物顶部**显式标注**「无法解析，本次未应用任何标记」 |
| `schemaVersion` 不是 `1.0` | 同上，并写明读到的是什么版本 |
| 某条缺 `targetId` | 跳过该条（不猜目标） |
| 其他键名（`conceptId` / `id`） | 兼容读取 |

> **为什么"读不懂"不算错**：这是一个尽力而为的增强输入。因为一个辅助文件格式变了
> 就让整次采集失败，会让工具在最需要它的时候（内容恰好出问题、你正想标记它）不可用。
> 但**必须显式标注**——否则"这次确实没有标记"与"这次没读到标记"在产物里长得一样。

### 5.3 生效方式

命中标记的 `targetId` → 该内容**强制红级**（F7 规则 R2），
且 `level_reason` 里带上标记的类型与说明。红级不产出可合入片段，必须人审。

### 5.4 存放位置

**必须放 `user.db`**（`PRD.md` §5.4 A1）：它从不参与内容替换，标记才能扛住内容更新。
导出路径由 Recall 设置页决定；beacon 用 `--flags` 指定，默认读 `./flags.json`。

## 6. 溯源链（NF-C7 / A-C15）

内容里任一最终字段都能反查到「哪次运行、哪个 URL、什么时间、什么响应」：

```
内容字段 ← proposals/<target>.yaml ← Candidate ← Observation ← 源响应
                                          │
                                          ├── run.meta.json 的 targetFingerprints（写回前的文档指纹）
                                          ├── observations.json（本次全部观测，含 provenance.raw_sha256）
                                          └── applied.json（写回了什么、跳过了什么、为什么）
```

一次运行目录的完整结构：

```
content-candidates/<运行id>/
├── changes.md          人只看这一个文件
├── proposals/          可直接合入的片段（**仅绿/黄**；红级不产出）
├── observations.json   本次全部观测
├── run.meta.json       运行元数据 + 各目标的写回前指纹
├── applied.json        apply 的结果（运行 apply 后生成）
└── pre-apply/          apply 前的原文快照（还原路径）
```

## 7. 版本与变更纪律

**`contractVersion` 何时必须递增**（破坏性变更）

- 删除 Feed 里的字段
- 改变字段语义（例如 `unit` 从"倍"改成"%"）
- 改变枚举取值集合
- 改变退出码含义

**何时不必递增**：新增可选字段、新增枚举值、内部结构（`Candidate`）变化。

**迁移说明**：每次递增必须在此处追加一小节，写明"旧调用方要改什么"。

### 1.0（2026-09-23）

首版。Feed 字段集：`indicator / period / value / unit / caliber / source / provenance`。
`source` 含 `channel`（与 `upstream` 分开：前者说"我们通过谁拿到"，后者说"这是谁的数据"）。
