## 2. 逐个源的实测记录

### 2.1 FRED —— ✅ 可用，且无需 API key

**这是本轮最重要的发现。** FRED 的 `fredgraph.csv` 端点**不需要 key**，直接返回完整历史 CSV：

```
GET https://fred.stlouisfed.org/graph/fredgraph.csv?id=DGS10
→ HTTP 200 | text/csv | 268,791 bytes | 5.69s
```

**真实样例**（2026-09-23 实测，最后两行）：

| 序列 | 含义 | 2026-09-18 | 2026-09-21 |
|---|---|---|---|
| `DGS10` | 10 年期美债收益率 | 5.01 | **4.96** |
| `DGS2` | 2 年期美债收益率 | 4.76 | **4.76** |
| `DGS3MO` | 3 个月期美债收益率 | 4.14 | **4.17** |

**派生值**（C3 公式复核的现成用例）：

- 10Y − 2Y = 4.96 − 4.76 = **+0.20**（未倒挂）
- 10Y − 3M = 4.96 − 4.17 = **+0.79**（未倒挂）

**对首版的意义**：`hotspot.data.yield-curve-inversion` 这个概念的 `dataviz` 序列与「内容截至」日期，**可以完全由这一个源支撑**。

**已知限制**

| 项 | 说明 |
|---|---|
| 层级 | **L2**——FRED 是美联储系统的官方数据服务，但数据仍属"分发"性质。**视作 L1 等效**需在内容中如实标注出处为 "Federal Reserve Bank of St. Louis (FRED)" |
| 官方 API | `api.stlouisfed.org/fred/series/observations` **需要 api_key**（实测返回 `error_code: 400, api_key is not set`）。**首版不用它**——CSV 端点已够，且省掉"用户准备 key"这一步 |
| 响应时间 | **波动极大：2.7s ~ 18.3s**（全量 268KB 时更慢）。**必须设长超时**（配 40s） |
| 字段格式 | 极简两列：`observation_date,<SERIES_ID>`。缺失值以 `.` 表示 |
| **HTTP 客户端** | ⚠️ **必须用 curl，不能用 Python 客户端（httpx / urllib）。见下方 2.1.1** |
| **UA 头** | ⚠️ **必须不发 `User-Agent`**。见下方 2.1.1 |
| 取数区间 | 用 `&cosd=YYYY-MM-DD` 限定起始日期。全量 CSV 是 1962 年至今（268KB），而我们只需要近一年——**不为了 200 个点去下载 16000 行** |

> ⚠️ **原设计要改**：`PRD.md` §3.2 把美财政部官网列为收益率曲线的**主源**、FRED 为交叉验证源。实测美财政部官网**网络不通（HTTP 000）**，而 FRED 可用。所以首版**主源改为 FRED**。
> 连带的后果是：这个指标**失去了 C1 跨源能力**（只剩单一源），依据 `PRD.md` §3.5 的规则，其定级从「预期绿」**降为「预期黄」**。

### 2.1.1 ⚠️ FRED 必须用 curl 且不能发 UA（P-C2 实测，最重要的运维发现）

**这不是网络波动，是确定性的客户端差异。** 同一台机器、同一分钟、同一个 URL：

| 客户端 | 结果 |
|---|---|
| `curl`（不带 UA） | **3/3 成功**，87–196 bytes（限区间后），2.4–5.7s |
| `curl -H "User-Agent: <Chrome UA>"` | **失败**——HTTP/2 `INTERNAL_ERROR` 或读超时 |
| `httpx`（默认 / 显式 proxy / `verify=False` / `Connection: close` / `trust_env=False`） | **0/3 成功**，全部 `ReadTimeout` |
| `urllib` | 同样超时 |

**对 httpx 的排除过程**（都试过了，都不是原因）：代理（环境里有 `HTTPS_PROXY`，但显式传 proxy 与直连都失败）、证书校验、HTTP/2、连接复用。
**对照实验**：同一进程里 httpx 访问 jsDelivr 1.8s 正常 → 说明不是 httpx 本身坏了，是**这个站点对 Python 的 HTTP 栈不响应**。

**由此产生两条硬约束**

1. **该源必须走 curl 后端**。配置写在 `beacon/config/sources.yaml` 的 `transport: curl`，实现在 `beacon/core/curl_transport.py`。
   > 它是**唯一**被允许调用外部进程的模块（`tests/test_independence.py` 用白名单钉死），
   > 且**默认后端仍是纯 Python 的 httpx**——避免"整个工具悄悄依赖本机装了 curl"。
2. **该源必须不发 `User-Agent`**。空 header 值 = 不发送该 header（`curl_transport.py` 里显式实现），
   配置里写成 `User-Agent: ""` 而不是留空或照抄别的源。

> 💡 **一般化教训**：遇到"命令行能通、代码不通"，先怀疑**站点对客户端指纹的拦截**，
> 并且**先做对照实验**（用同一份代码访问一个已知可达的站点）来区分是"代码坏了"还是"这个站点挑客户端"。
> 这次若不做对照，会误判成"httpx 有问题"而去换库，方向就全错了。

### 2.3 中证指数公司 —— ✅ 可用（且是首版唯一的 L1）

```
GET https://www.csindex.com.cn/csindex-home/perf/index-perf
      ?indexCode=000300&startDate=20260801&endDate=20260923
→ HTTP 200 | application/json
```

**真实样例**（2026-09-23 实测，38 条日度记录）：

| 交易日 | PE | 收盘 |
|---|---|---|
| 2026-09-22 | **13.53** | 4544.59 |
| 2026-09-21 | 13.51 | 4539.57 |
| 2026-09-18 | 13.42 | 4507.39 |

完整字段：`tradeDate, indexCode, indexNameCn(All), indexNameEn(All), open, high, low, close, change, changePct, tradingVol, tradingValue, consNumber, peg`

## 4. 对 PRD 的修正（P-C1 的实质产出）

实测推翻了三处写在 `PRD.md` 里的假设。**按项目规矩，修正要落回 PRD，不能只在这里记一笔。**

### 修正 1：统计局新版接口路径是错的（我的失误）

`PRD.md` §3.2 写的 `data.stats.gov.cn/dg/website/publicrelease/web/external`（"V2.0，2026-03 更新"）**实测不存在**。该信息来自搜索结果，我当时未核实就写进了 PRD。

### 修正 2：收益率曲线的主源改为 FRED，定级从「绿」降为「黄」

美财政部官网不可达。主源改 FRED 后**只剩单一源**，失去 C1 跨源能力，按 §3.5 的规则**必须降级为黄级**。

### 修正 3：⚠️ 「不依赖任何 L2」这个约束在现有网络环境下不成立

`PRD.md` §1.2 写的首版原则是「4 个主源全部是官方机构、**不依赖任何 L2 非官方接口**」。实测结果：

| 首版 4 个指标 | 原定主源 | 层级 | 实测 |
|---|---|---|---|
| PMI | 国家统计局 | L1 | ❌ 不可用 → 需用**东财（L2）** |
| 社融 | 中国人民银行 | L1 | ⚠️ 未验证 → **移出首版** |
| 收益率曲线 | 美国财政部 | L1 | ❌ 不可达 → 需用 **FRED（L2）** |
| 估值分位 | 中证指数 | L1 | ✅ 可用 |

**4 个里只有 1 个能坚持 L1。** 也就是说，"不依赖 L2"这条要求是**建立在一个不成立的假设上**（官方源都能用）。

**这不是"放宽标准"，是修正一个基于错误假设的需求。** 建议改为：

> **L1 优先，但 L1 不可达时允许使用 L2，且必须满足三条**：
> ① 该 L2 源的数据**源自官方**（FRED 属此类；东财转发的也是官方统计）
> ② 必须在 `source` 字段**如实标注**为 L2 及其上游
> ③ 必须有 `healthCheck`，失败时不产候选

### 修正 4：首版指标从 4 个减为 3 个

**社融移出首版**（央行数据未定位到可程序化获取的形式）。

调整后的首版范围：

| # | 概念 | 主源 | 层级 | 校验手段 | 预期定级 |
|---|---|---|---|---|---|
| 1 | `hotspot.data.yield-curve-inversion` | FRED | L2 | C2 + C3（利差恒等式） | **黄** |
| 2 | `hotspot.data.pmi-reading` | 东方财富 | L2 | C2（制造业/非制造业口径）+ 可选第二个 L2 源 | **黄** |
| 3 | `hotspot.data.valuation-percentile` | 中证指数 | **L1** | C3（分位公式复核） | **黄** |

**全部预期为黄级——首版没有任何绿级指标。** 这是诚实的结果：绿级要求"通过该指标声明的交叉校验"，而首版三个指标都只有单一可用源。

> **对预期的校准**：`PRD.md` 的目标 G2 是"绿级占比 ≥60%"。**首版做不到，因为没有指标具备跨源条件。** 要拿到绿级，前提是同一指标有第二个独立源——那需要先解决"多源可达"的问题（例如自建镜像、或找到可用的第二源）。这个目标应当在 v1.1 重新评估，而不是在首版硬凑。

## 5. 首版技术与行为约定（由实测倒推）

| 项 | 约定 | 依据 |
|---|---|---|
| 超时 | **≥30s**（FRED 单次 5.7s，需留余量） | 2.1 |

| **美债收益率**的第二个源（美国财政部官方 API） | `api.fiscaldata.treasury.gov` 无响应、`home.treasury.gov` HTTP 000 → **均不可达** |

> 结论：**`hotspot.data.yield-curve-inversion` 在首版只有 FRED 一个源**，
> 无法做 C1 跨源对照，定级只能是**黄**。这与 §4 修正 2 的预判一致，已确认无翻盘可能。

### 7.1 它要回答什么

内容库的图表里，凡是数字来自"为了讲清道理而编的"，块级 `source` 都写着「示意数据」。
问题是：**哪一些本该换成真实数据，哪一些本来就该是示意图？**

这个判断不能凭感觉——它决定了后面所有扩指标动作的范围。所以逐处判定，并写明依据。

### 7.2 判定标准（三条全部满足才算「替换真实」）

| # | 条件 | 说明 |
|---|---|---|
| 1 | 图上画的是**可测量的量** | 时间序列或横截面；不是假设、不是文献结论、不是统计关系 |
| 2 | 存在**可达的公开源**（已实测） | 没实测过的不算"可达" |
| 3 | 图的**语义槽位与数据形态相容** | 例如"三种典型形态"需要三个时点，而源能给到 |

任一条不满足 → 判定「保留示意」，并注明是**哪一条**不满足。
这样判定可复核：不同意结论时，只需反驳那一条。

### 7.4 三组「保留示意」的区别（不是一回事）

这三组都不能替换，但**原因完全不同**，处理方式也不同：

| 组 | 为什么不能替换 | **该做什么** |
|---|---|---|
| **C** | 图上画的**不是一个可采集的量**（文献结论 / 假设性计算 / 自有研究） | **把「示意数据」这个标签改准确**：文献结论要标文献，假设性计算要标假设，自有研究要标来源。**不是保留"示意"二字就完事** |
| **D** | 量是可采集的，但**源没解决**或**不属首版范围** | 按 v1.1 计划推进；社融要先解决央行数据获取 |
| （B） | 量可采集，源**本轮没找到** | 继续找源；找不到就并入 C 或 D 并写明 |

> ⚠️ 这一区分是有代价的教训：C 组里有 5 处（#14、#17、#18–21）如果一直挂着"示意数据"，
> 读内容的人会以为"这些数字是将就用的、以后会换成真的"——而实际上它们**本来就该是那样**。
> 「示意数据」这个标签的语义含糊，同时掩盖了"待替换"和"本就如此"两种情况。
